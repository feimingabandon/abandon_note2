# 天气刷新与万年历：整合实现方案

日期：2026-09-28。适用于当前工作区的本次实现，尚未发布安装包。研究依据见 [原评估](2026-09-28-weather-refresh-and-almanac-design.md)。

## 1. 产品入口与使用方式

| 位置 | 行为 |
|---|---|
| 列表极简模式 | 保留工具栏今日宜忌摘要，不给便签卡片重新添加小组件 |
| 万年历弹窗 | 前一天、日期选择器、后一天、今天；浏览农历、闰月、节气、节日与已知休班安排 |
| 列表工具栏左侧 | 今天的宜、忌两行摘要按可用空间动态分配宽度，末尾额外留白 24rem，超出时右侧渐隐；点击打开今天详情，极简模式同样显示 |
| 月周工具栏天气右侧 | 今日宜、忌摘要按可用空间动态分配宽度，末尾额外留白 32rem，超出时右侧渐隐；点击查看今天详情 |
| 默认内容 | 宜忌直接提供，没有开启开关；旧关闭记录不再生效。详情显示完整宜忌、特殊结论、常见术语释义、年/月/日干支、建除及规则来源 |
| 月周日期侧栏 | 两行宜忌摘要，各最多三项；“查看全部”进入对应日期的完整万年历 |

| 月周日期格顶部 | 按所在日期优先显示天气，无可用天气时只显示“宜忌”两个字，点击打开对应日期小浮层 |

按最新要求，已移除列表、月、周标题栏的万年历按钮及日期格右键的“查看万年历”，后续入口另行确定。现有宜忌摘要及详情功能保留。

日期格在原天气位置显示天气或宜忌，不增加新的固定行。弹窗复用 `AppModalShell`、`DatePicker`、全局材质与动效；内容内部滚动，支持 Escape 和关闭后恢复入口焦点。摘要与日期内容短淡入，来源说明平滑展开收起。快速选日期时清除旧结果并用请求代次丢弃过时响应，不把旧宜忌放到新日期下面。默认跟随今天时跨午夜更新，主动查看其他日期时保留选中日期。工具栏摘要展示完整条目并在实际超宽时右侧渐隐；月周剩余可用宽度较小时将导航移至第二行。

## 2. 天气刷新策略

继续使用免 Key 的 Open-Meteo。中国地区保留 CMA GRAPES 与自动模型补齐；一个刷新批次通常两次 HTTP 请求，其他地区通常一次。没有增加新后端或用户密钥。

| 场景 | 实现 |
|---|---|
| 正常展开显示的主窗口 | 每次现有分钟调度检查是否到期；成功获取满 30 分钟后更新，并附加 0～60 秒随机延迟 |
| 无缓存/切换地区 | 统一协调器按需获取，已有缓存立即呈现 |
| 隐藏、最小化、灵动岛、锁屏、休眠 | 暂停自动请求；锁屏与休眠分别记录 |
| 显示、恢复、解锁、唤醒、重新联网 | 检查到期，只补一个批次，不追补错过的周期；仍受退避限制 |
| 手动更新 | 复用同地区在途请求；两次尝试至少间隔 5 分钟 |
| 普通网络失败 | 自动按 5/15/30/60 分钟退避，最大 60 分钟；成功清零 |
| 服务端限流 | 遵守 429 的 Retry-After；手动更新也不能绕过 |
| 参数/鉴权类 4xx | 暂停重复请求，等待天气设置改变 |
| 天气关闭或 A→B→A 地区切换 | 用设置代次拒绝过时结果的发布与缓存提交 |

新天气通过 IPC 更新局部天气区域，不刷新便签或触发整页动画。冷读取、自动刷新、恢复窗口与手动更新只有一个请求协调器；缓存写入串行化，磁盘写入失败保留本次有效内存结果，不把它当成网络失败重复获取。

### 展示与过期

- 月周工具栏优先显示当前天气和当前温度；当日侧栏保留当前读数与全天预报。当前字段无效时，工具栏明确显示“今日预报”。
- 日期格和便签卡片使用全天天气码及最低～最高温度；不能用当前晴天覆盖全天雷阵雨预报。
- 普通详情和悬停提示显示获取时间；更新失败显示旧数据提示，失败不推进成功时间。
- 当前天气两小时后提示较旧，六小时后或跨天气地区日期后隐藏；全天预报六小时后提示较旧，24 小时后隐藏。
- 使用共享分钟时钟驱动过期检查；新响应到达时使用实际时间即时判断，避免响应比最后一个分钟 tick 新而短暂消失。
- 缓存升级到版本 3，兼容旧缓存并恢复原日预报码。`generationtime_ms` 不作为发布时间。

30 分钟提高信息及时性，不代表预测准确率提高。免费托管接口的使用条件与配额仍适用，见原评估的官方资料。

## 3. 离线历法与宜忌规则

农历、节气和节日继续复用 `chinese-days`；官方放假调休继续由原有节假日数据服务提供。未来官方调休不能由宜忌计算出来。

宜忌使用 `cnlunar-js 0.2.0`，固定上游提交 `b7daa47198f7370c4f75d43be1667407f164c4f2`，保留 MIT 许可证并随资源打包。原规则参考《钦定协纪辨方书》，不宣称“官方统一宜忌”，也不混入梅花起卦、个人八字或时辰择日。

固定口径：春节换年、交节日期换月、`godType=8char`、`year8Char=year`、`yeargod=duty`；只计算选中的 `YYYY-MM-DD`，内部固定取当日中午。模块内 `CivilDate` 用 UTC 容器表达同一个中国民用日期，隔离宿主时区和夏令时，不更改应用全局时区。规则版本为 `xieji-8char-year-duty-civil-noon-1`。

**宜忌支持 1901-02-19～2099-12-31。** 检查发现上游虽有 200 年节气数据，农历月份表实际只有 199 年，越界使用取模会循环回早年数据，已在入口阻断。原日历的 1900～2100 年范围不缩小；越界只提示宜忌暂不支持。

保留引擎已经完成取舍的结果，应用不添加“忌优先”等自创结论。特殊的“诸事不宜”“诸事不忌”“余事勿取”与普通事项分开；空结果、越界、失败分别表达。若原规则仍有同项交叠，保留两侧并说明。术语释义仅解释古词。

按日期查询，内存缓存上限 256 天；不预生成几十年的字符串，不访问每日黄历 API。规则和历法数据修订随应用更新，进程内缓存随版本更新重建；官方节假日安排按现有流程单独更新。

## 4. 代码边界

- `weather-refresh-controller` 统一调度策略，`weather-service` 负责请求、双模型和持久缓存；共享 freshness/display 模块负责时间语义。
- `almanac-engine` 包装固定来源，`almanac-service` 合并日期元数据；授权的日历 IPC 和 preload 桥接访问。
- 万年历只读，不修改便签数据模型。已移除宜忌设置的 schema、application settings、主进程写入白名单与界面组件；历史数据库残留值不会关闭宜忌，无需改动用户数据。
- 列表、月周共用万年历组件；保留工作区原有其他修改，不提交或发布。
