# 独立截图与贴图核心功能设计

日期：2026-09-28

## 1. 已确认的产品约束

- 截图、贴图与 Abandon Note 同生共死。隐藏主视图、收起到托盘不等于退出；应用完全退出后，不留下截图进程、贴图窗口或截图快捷键。
- 支持在其他软件和桌面上通过全局快捷键截图，不依赖便签新建、编辑或背景设置页面。
- 产品基准是 Snipaste 免费版的核心截图、贴图、标注、快捷键和操作栏。完成要求包括操作语义、持续反馈、连续编辑和错误恢复，不能只按同名按钮或工具数量验收。
- 不强求采用任何开源项目。默认继续使用自有 C++/Qt 引擎；在明确减少实现或维护成本时才局部复用，不能由上游现成功能反过来决定产品行为。
- 对齐日常交互，不复制品牌素材；免费版中的外围能力另列，专业版专属功能不自动加入范围。本文未核实的视觉/焦点细节须实机对照后记录，不能将推测标成已对齐。
- 保留现有便签附件和应用背景入口，统一调用新引擎。
- 当前交付平台为 Windows 10/11 x64；覆盖范围必须与最终选定的 Qt 版本及项目 Windows 最低版本一致。
- 按最终架构实现和验收，内部可以拆任务，但不能把一个只能截图的中间版本标记为本方案完成。

### 2.1 核心与扩展的边界

- 先完成截图、标注和贴图的整条操作链。自动框选、放大镜、贴图再次标注、文字旋转、贴图旋转/镜像、关闭恢复不再沿用 v1 的排除项。
- 免费版也具有的延时截图、白板、开始截图前预设尺寸、成功截图历史回放、自动保存、贴图分组、文字/HTML/颜色转图，列为后续扩展，暂不进入核心交付门槛。这是产品取舍，不表示它们属于专业版或毫无价值。
- OCR、二维码、专业版任意旧对象直接点选重编辑、贴图裁剪/多选等不作为免费版核心要求；翻译、滚动长截图、录屏、云同步和插件系统不属于本次主线。
- 当前仍不做多个文件批量贴图、动画播放和跨重启恢复；跨显示器拼接已纳入本轮范围，真实多屏、混合 DPI 与会话内关闭恢复必须覆盖。单屏上的合成布局测试不能替代真实双屏验收。
- 全局快捷键默认值、原托盘左键行为和便签/背景动作保留本应用约定。局部截图/贴图操作尽量按免费版常用语义对齐；差异须明确登记，不能默默降低要求。

这些边界不构成对 Snipaste 免费版全部功能已复刻的声明。C01—C12 与配套 UX01—UX10 的核心行为缺失即未完成。

## 3. 对用户的具体行为

### 3.1 快捷键与托盘

- 默认绑定：截图 `F1`，允许修改和清空；保留用户已有自定义值。剪贴板贴图及显示/隐藏全部贴图没有全局快捷键，仅通过托盘操作。
- 托盘“禁用全部快捷键（本次运行）”复选项统一控制截图及视图显示。禁用时勾选并在托盘图标叠加红色禁用标记，注销按键但保留配置；修改/取消录制、切换视图和隐藏到托盘继续保持禁用。完整退出并重启后恢复启用和正常图标，忽略旧版保存的禁用值，不重置自定义按键。窗口内编辑、复制等操作仍可使用。
- 应用内重复绑定应在保存前阻止；被系统或其他软件占用时显示该动作未启用，托盘入口仍可使用，不静默替换为其他按键。
- 录制快捷键时暂停可能被录制操作触发的应用全局动作，完成、取消、设置页销毁后恢复；保留已存在的视图显示快捷键。
- 全局快捷键由 Electron 唯一持有，Qt 只处理自己的窗口内快捷键。
- 截图活动期间，再次触发截图仅聚焦当前会话；贴图及显示/隐藏贴图动作暂不执行，以免打断冻结画面。结束后恢复。
- 没有贴图时，“显示/隐藏全部贴图”为无副作用操作。剪贴板不是受支持的图片时，给出可见反馈，不创建空窗口。
- 沿用现有托盘左键的主视图显示/隐藏行为，在右键菜单新增截图、贴图及贴图显示/隐藏，不抢占原托盘操作。

### 3.2 截图与标注

1. 记录启动来源、当前主视图可见性、前台窗口和截图前的贴边/层级状态。
2. 按现有“截图时隐藏主视图”设置暂时隐藏主视图；原本隐藏的主视图继续隐藏。默认沿用现有设置值，不改写用户偏好。
3. 捕获显示器图像后，再显示各显示器的选区层；透明实时桌面不作为标注底图。
4. 鼠标所在显示器为初始活动屏幕；没有选区时，可移到其他屏幕框选。选区一旦建立即绑定该屏幕，拖动/调整在该屏幕边缘截断；右键清除后可重新选择另一屏。
5. 选区至少为 1×1 个实际图像像素。方向键移动选区 1 像素；Ctrl+方向键向外扩大对应边界，Shift+方向键向内缩小对应边界。拖拽框选或调整边缘时按住空格可平移，松开恢复原拖拽；WASD 微调光标。文字输入期间字符和编辑按键交给文字编辑器。
6. 标注存储在选区对应的屏幕图像坐标中；移动或调整选区改变裁切窗口，已有标注保持图像位置，最终导出裁切范围内的内容。界面预览必须和导出一致。
7. 标注时右键结束当前图案并保留有效内容，不能把“结束编辑”实现为丢弃文字；没有当前图案时清除选区，无选区时取消截图。Esc 优先交给 IME/当前输入状态，最后取消会话；具体各状态的顺序必须记录并实机对照，任何取消都清除鼠标捕获和拖动状态。
8. 非编辑状态下，选区内左键双击或 Enter 复制并完成；中键或 Ctrl+T 直接贴图；全屏使用 Ctrl+A 或明确按钮，不再用选区内双击改为全屏。编辑文字/图案中的双击由编辑器处理。
9. 标注包含“新建中、当前可编辑、已完成”阶段，松开鼠标不应立即失去当前图案的调整能力。切换工具/右键结束/输出时按同一规则提交，空文字不产生历史项。撤销到目标图案消失再重做，恢复为当前可编辑图案；不要求直接点选任意旧图案的专业版行为。
10. 无选区时自动检测普通窗口与可访问的界面元素，Tab 切换检测类别；不可访问或检测失败时保留手动框选能力。检测结果只确定冻结底图上的矩形，不能重新抓取不同帧。R 恢复上次成功区域；原显示配置失效时不能沿用错误坐标。
11. 放大镜显示像素、坐标和颜色；Alt 可呼出，显示时 C 复制色值、Shift 切换 RGB/HEX。它不进入导出图像，且不得遮住当前定位点或跑出屏幕。

文字支持多行、字体、字号、颜色、中文 IME，以及当前文字的移动、四角缩放和旋转；右键结束仍保留文字。工具参数按类型生效，马赛克块大小和模糊强度不能共用无效的线宽数值。橡皮擦作用于标注层，不抹掉截图底图。矩形/椭圆、线/箭头等的 Shift 约束按免费版文档验收；折线拖拽画单线、多次点击续接折线。标注预览与实际导出采用同一渲染结果。

### 3.3 操作栏与输出

- 操作栏优先放在选区下方；空间不足时尝试上方，再退回屏幕内侧。水平和垂直都必须限制在当前屏幕可用范围内。
- 窄屏或大缩放时将次要动作收入“更多”，不能用横向溢出隐藏复制、保存、贴图和取消。
- 框选阶段提供简短操作提示及“全屏”入口；有选区后展示工具栏和实际像素尺寸。
- 工具按钮提供图标、名称/快捷键提示和明确选中态；颜色、适用粗细/字号等在邻近参数条呈现，不能只藏在“更多”或模态对话框。工具切换后更新光标和参数反馈；不适用的参数隐藏或禁用，避免出现可改但无效果的控制。
- 非拖动/文字输入状态的空格切换工具栏显隐，不丢失选区/图案；标注态滚轮、1/2、[/] 调整适用的笔宽/字号，并立即反映到当前对象或下一笔预览。全局颜色等偏好可以保留，但不要求专业版各工具独立颜色记忆。
- `Ctrl+C`：复制；`Ctrl+S`：保存；`Ctrl+Shift+S`：快捷保存；`Ctrl+T`：贴图；`Ctrl+Z`/`Ctrl+Y`：撤销/重做。Ctrl+Shift+Z 为清空全部标注，不再沿用 Qt 默认的重做映射。文字焦点或 IME 合成期间，剪贴板与编辑按键优先交给文字输入。
- 快捷保存使用用户明确设置的目录；目录未配置时提示设置，不擅自选择位置。保存路径不可写时保留编辑现场。它与每次截图自动保存属于不同能力。
- 复制/保存/贴图成功后结束当前截图；失败时保持原选区、标注和冻结图像，并提示可重试。取消文件选择器也返回原现场。
- PNG 保留像素精度；JPEG 的透明区域以白色合成为不透明图像。文件扩展名、编码及实际内容必须一致。
- 文件保存采用同目录暂存、成功后替换；覆盖需走系统确认。失败不能截断已有目标文件。
- 截图浮层不得把自身遮罩、选区线、操作栏或鼠标提示绘入结果。复制到剪贴板需保留操作系统拥有的有效图像，不能依赖马上被销毁的内存句柄。

### 3.4 入口与结果去向

| 来源            | 主要完成动作         | 其他行为                                                     |
| --------------- | -------------------- | ------------------------------------------------------------ |
| 全局快捷键/托盘 | 复制、保存文件、贴图 | “更多”提供新建图文便签、用作应用背景                         |
| 新建/编辑便签   | 添加到当前便签草稿   | 仍可复制、保存文件、贴图；不会因此提前提交便签               |
| 背景设置        | 用作应用背景         | 打开原有背景裁剪流程，确认前不替换背景；仍可复制、保存、贴图 |

- 将截图加入草稿时，继续遵守附件数量、单张大小和新增总量上限；失败必须保持截图，不能静默丢弃。
- 全局“新建图文便签”创建独立待编辑草稿，不隐式修改当前正在编辑的其他便签。
- 已有草稿阻止打开新页面时，沿用现有草稿保护；用户取消页面切换后，图片仍留在截图会话，可以改为复制/保存/贴图。
- 来源表单关闭或被替换时，不向旧组件交付。保留图像并显示来源已不可用，允许选择独立输出动作。
- 只有接收方确认已接管图像后才结束会话并释放暂存资产。取消背景裁剪不覆盖旧背景，不遗留无引用的永久文件。
- 全局截图完成或取消后，主视图恢复原可见性、几何、贴边和层级；不因复制或保存强行弹出主视图。前台焦点尽力恢复，Windows 拒绝焦点切换不能留下不可操作状态。

### 3.5 贴图

- 贴图是临时参考图，不创建便签记录；截图后贴图不要求主窗口可见。
- 每张贴图有独立编辑文档、位置、缩放、透明度、旋转/镜像和可见状态。截图转贴图须保留可继续标注的文档，不能只保留不可变显示图；新增标注使用与截图相同的编辑模型和工具栏。
- 默认置顶；现有单张置顶开关可保留为附加能力，但不替代免费版核心要求。非编辑态拖动移动窗口，滚轮/加减/边缘拖动等比例缩放；Ctrl+滚轮或 Ctrl+加减调整透明度；方向键逐物理像素移动。编辑态鼠标与滚轮交给当前工具，不能同时移动/缩放窗口。
- 中键同时恢复 100% 大小和 100% 不透明，一个图像像素对应当前显示器的一个物理像素；菜单提供同等动作。透明度沿用本产品 20%—100% 下限，并明确记录为产品约定，不声称与参考软件范围完全一致。
- 支持 1/2 顺/逆时针旋转 90°、3/4 水平/垂直镜像、Shift+双击固定缩略图，以及 Shift 拖动吸附对齐。文字输入和标注态优先处理其自身按键，不能意外旋转整个贴图。
- 空格显示/隐藏标注工具栏，Ctrl+C/Ctrl+S 复制/保存当前内容。导出包含已提交标注和内容旋转/镜像；显示缩放、窗口透明度、阴影、边框及工具栏不烘焙到输出。文字和未完成图案按截图的同一规则处理。
- 贴图内容始终接收鼠标输入，不提供鼠标穿透。外围装饰光晕仍不拦截输入，以免扩大图片的点击区域。
- 隐藏全部保留全部状态；关闭（非编辑态 Esc/双击/Ctrl+W）移出可见窗口，保留最近一张关闭记录供会话内恢复；销毁（Shift+Esc/菜单）立即释放且不能通过恢复找回。编辑态 Esc 先结束当前输入或隐藏工具条，不能一律销毁贴图。
- 提供“恢复最近关闭贴图”明确菜单入口。参考软件贴图键对剪贴板新内容/相同内容/已关闭记录的优先级需实机对照后固化，不自行猜测；此项记为待核对交互。新图创建失败不得挤掉恢复记录。
- 不提供关闭全部贴图入口。单张销毁、恢复队列淘汰和完全退出必须释放图像、标注与历史；普通关闭保留的部分仍计入会话预算。没有跨重启恢复。
- 把图片交给便签草稿时必须复制或转移为草稿拥有的资产，不能在关闭贴图后让附件失效。

### 3.6 实现前的交互约束

- 截图和贴图共享文档、标注命令、工具参数及工具栏组件；窗口移动/选区调整/图案编辑各自持有明确输入状态，不用零散按键分支相互覆盖。
- 右键完成、Esc 取消、失焦、系统关闭、输出失败和重做恢复都必须测试“下一次操作还能继续”，而非仅检查当前窗口未崩溃。
- 参数弹窗属于当前编辑工作区；失焦不能把打开调色板或字体控件误判为结束截图。文字内容、选区和当前图案必须保留。
- 对官方文档未明确的悬停外观、光标、焦点、贴图恢复优先级、动作细小阈值，先实机记录再决定，不用当前代码行为当作期望。任何有意差异应有产品理由和对应测试。

## 4. 最终架构

### 4.1 模块划分

采用 C++20 / Qt 6.8.3 Widgets 独立引擎进程，Electron 保持宿主地位。Qt 控件和绘制用于工具栏、文字编辑、图像标注及贴图；Windows 专属功能封装在捕获和生命周期后端。

已实现的目录：

```text
src/main/capture/
  CaptureCoordinator.js       # 入口、单会话、主视图恢复、业务交付
  CaptureHost.js              # 引擎启动、协议、异常、退出
  CaptureShortcutService.js   # 截图与视图显示快捷键、录制和总开关协调
  CaptureAssetStore.js        # 临时文件所有权、大小检查、清理
  capture-image-worker.mjs    # PNG CRC/解码边界校验及 Base64 编码
native_capture/
  engine/                    # Qt 窗口、选区、标注、贴图
  platform/windows/          # 屏幕捕获、显示器/DPI 与父进程约束
  host/                      # 小型 C ABI 生命周期 DLL
  tests/                     # 纯算法和 QtTest
```

- 不将 Qt 窗口和绘制逻辑放进现有 `blur_engine.dll`，也不加载到 Electron 主进程内执行。
- 宿主 DLL 只承担原生受控进程启动/Job 生命周期，采用短时、无 JS 回调的 C ABI；进程通信交给异步 IPC。
- 已有 `ScreenshotPicker` 和背景组件成为调用入口；新的引擎替换内嵌 HTML 选区实现，避免长期维护两套交互。
- 捕获后端从引擎界面中分离。首选支持普通 SDR 桌面静态捕获的 Win32 实现；Qt 显示器坐标和原生图像尺寸显式关联。HDR 色彩准确性、受保护画面不作无证据保证，见测试章程。
- Qt 版本、MSVC 运行库和 Windows 最低版本在构建配置中固定；不能直接继承现有模糊 DLL 的静态运行库选项来假设 Qt 二进制兼容。

### 4.2 同生共死的进程约束

1. 应用完成初始化后异步启动并预热一个截图引擎，完成握手前托盘/按钮显示启动状态，快捷键请求合并为一个，不能创建多个进程或截图会话。
2. 宿主先创建设置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 的专用 Windows Job，通过 `STARTUPINFOEX` 的 `PROC_THREAD_ATTRIBUTE_JOB_LIST` 在 `CreateProcessW` 创建引擎时直接加入 Job。可以同时挂起创建再恢复，但不能使用“创建进程后再加入 Job”作为唯一保护，否则两次调用之间宿主崩溃会留下孤儿。Job 句柄只由宿主持有且不可被子进程继承。
3. 这样宿主正常退出或崩溃、句柄关闭时，引擎及其受控子进程由系统终止；不能仅依靠 JS 的 `before-quit` 事件或父 PID 轮询。
4. Qt 同时监听宿主 IPC 断开，主动结束窗口。引擎不设置自启动项、独立托盘和独立更新器。
5. 用户发出退出请求时，先执行当前项目的草稿退出确认。用户取消退出时，截图引擎、贴图及快捷键保持可用。
6. 真正进入退出后：禁止新请求、注销本功能快捷键、取消会话、要求引擎关闭窗口并释放资源；最多等待 2 秒，然后只终止本应用专用 Job。不得按进程名称批量结束 Qt 或 Electron。
7. Job 属性初始化或受控创建失败时，不降级为无生命周期约束的后台进程，报告截图功能启动失败；便签主功能仍可运行。宿主已有的外层 Job 限制也要纳入创建失败测试。
8. 引擎异常退出时，当前截图失败并恢复宿主状态，已有临时贴图丢失且给出提示；下一次用户触发允许重启一次。连续启动失败需明确重试，不能无限自动重启。

### 4.3 IPC 和图像所有权

- 协议版本与应用版本分开；请求带 `sessionId`、`requestId`、来源类型和来源草稿令牌。过期或重复终态消息不再执行。
- 使用当前用户受限的本地命名管道，握手带每次启动的随机令牌；非本次引擎不能操作会话或提交文件。
- 控制消息为有大小上限的 JSON；图像通过宿主创建的会话目录中的 PNG 文件交付，响应仅带资产 ID、尺寸和字节数，不接受任意外部路径。
- 宿主验证资产位于该会话目录、格式可解码、尺寸和大小未超限，再交给附件或背景流程。
- 引擎拥有冻结底图和当前标注；资产存储拥有输出暂存文件；附件草稿或背景流程确认接管后各自拥有副本。取消和失败只清理本会话资产。
- 全局截图、便签截图、背景截图共享一个会话锁；贴图管理可以有多个窗口。

### 4.4 状态与失败规则

```text
空闲 -> 准备 -> 捕获底图 -> 选区/标注 -> 输出中 -> 成功 -> 清理 -> 空闲
                         |             |
                         |             +-> 输出失败/取消文件对话框 -> 原选区/标注
                         +-> 取消/来源失效后用户取消 -> 清理 -> 空闲
任意活动状态 -> 引擎异常/显示配置失效 -> 失败 -> 恢复宿主 -> 空闲
任意状态 -> 确认退出 -> 关闭中 -> 已停止
```

- 每次截图只释放一次贴边暂停，只恢复一次窗口状态，结果只完成一次。
- 锁屏/挂起或显示器拓扑、DPI 在截图中变化时取消当前截图，丢弃旧坐标，保留已经完成的贴图；恢复后重新枚举屏幕。
- 显示器移除时，将贴图约束到剩余显示器可见区域；恢复位置时保留可操作部分。
- 输出期间禁止重复确认。取消与完成竞争时按第一个已提交终态处理，后到消息不得影响下一次会话。
- 图像采集、编码、文件保存和资源释放均不得长时间阻塞 Electron 主线程。

### 4.5 坐标与资源

- 会话以 Windows 原生桌面坐标拼接各屏原始图像，不缩放各屏内容。选区、标注及导出使用统一物理像素；Qt 逻辑坐标只用于显示和控件。桌面未被显示器覆盖的空隙在 PNG 中透明。Ctrl+A/F 选择鼠标所在显示器，跨屏截图使用连续拖选。
- 手动框选、移动和八向调整可吸附到可见窗口边缘和显示器边界；阈值按鼠标所在屏幕换算约 6 个逻辑像素。被遮住的窗口边缘不参与。按住 Ctrl 暂停吸附，方向键保持逐物理像素调整。绘图工具不使用选区吸附。
- 选区使用半开区间 `[left, right) × [top, bottom)`，端点映射到整数像素后限于图像边界，输出尺寸等于端点差。键盘微调直接作用于实际像素坐标。
- 标注预览和最终图像合成使用同一坐标转换与绘制规则。
- 建议本版活动/隐藏贴图与关闭恢复记录合计最多 10 张，图像预算最多 512 MiB；保留最近一张关闭记录也计入限制。超限保留已有文档并反馈，不自动删除仍在使用的贴图；关闭记录仅按明确的队列淘汰规则释放。编辑历史与缓存另计入实际内存预算。这是拟定产品上限，须经资源专项验证后锁定。
- 截图底图合成后的虚拟桌面包围矩形最多 128 MiB、活动图像总量 512 MiB；屏幕间空隙也计入画布面积，超限明确失败而不降采样。采集临时图像和拼接缓冲在分配前计入预算。支持的图片输入最多 50 MiB 编码数据且解码后最多 128 MiB；不能只检查文件大小。
- 标注历史最多 100 个已完成动作；超出后丢弃最旧的可撤销记录并提示，不删除已呈现标注。尽量保存绘制命令，避免每次撤销都复制整张 4K 图像。
- 内存预算包含底图、合成中间图、贴图和工具缓存；上述上限不代表进程总 RSS 上限。超大输出编码前应检查预算，失败时保留原编辑状态。
- 本地诊断记录会话阶段、来源、耗时、显示器配置、结果和错误码，不记录截图、剪贴板正文、图片 Base64 或便签内容。

## 5. 实现与交付原则

- Qt 原生界面延续应用的语义颜色、对比度和交互风格；Electron 设置和入口改动严格遵循 `docs/UI_DESIGN_STANDARD.md`。
- Qt 图像插件、平台插件、MSVC 运行库、宿主 DLL 和引擎 EXE 一起部署到应用资源目录，不依赖开发机 PATH 或 Qt 安装。
- 只选取需要的 Qt 模块；开源项目用于参考状态模型、算法、测试和局部实现，不设“必须先集成 kImageAnnotator/Snow Shot”等前置条件。复用代码时保留许可和出处；不为接入上游改写已确定的交互要求。依赖库的功能存在不等于本应用完成验收。
- 新引擎启动/IPC 失败时应显示真实错误；不得悄悄退回行为不同的旧截图实现，造成“功能已支持”的假象。
- 窗口、显示器和进程异常测试使用隔离配置，不操作用户真实便签和图片；只结束测试自己创建的进程。
- 开发顺序为共享文档/编辑状态、工具条与截图交互、贴图编辑/会话、业务集成和设备专项；阶段产物只能标明对应范围。C01—C12、T01—T23 和 UX01—UX10 的必要条件有证据后，才能称本核心基线完成。

## 6. 评估结论

按用户最新决定，后续以 Snipaste 免费版核心体验为目标，保留 Electron/Qt 生命周期与业务边界，修正选区、标注、工具条和贴图交互。开源调研提供参考材料，不再以选择第三方底座作为主线。v1 的六工具绘制和输出链路结果不足以证明 v2 完成。

不承诺未经测试的启动速度、内存占用和全部硬件兼容性。以配套测试章程中的功能映射、真实画面检查和故障恢复断言作为完成依据。
