# 全局 UI 一致性与响应式改造方案

编写日期：2026-09-30。状态：方案已编写，功能改造与本方案验收尚未执行。

本文供后续修改代码和测试时逐项对照，覆盖全局字号与界面缩放、响应式布局、公共控件、颜色、浮层、键盘交互和动画。目标是在不同窗口尺寸与 Windows 缩放比例下，保持清晰、稳定、协调的阅读和操作体验。

用户已确认保留全局字号体系与响应式布局，解除根字号与窗口宽度的直接比例关系；风格参考 macOS 的清晰层级、克制材质和连续反馈。本文中的尺寸和动效数值是本项目的实施初始方案，不是苹果官方规定。

本次授权为编写方案。本文中的任务、拟新增测试与设置均不能视为已经实现或通过验收。

## 1 依据与工作边界

- 本方案依据本次对话确认的方向和当前源码审查结果。`docs/UI_DESIGN_STANDARD.md` 仅作为历史设计记录，不作为本轮风格判定基准；与用户新方向冲突的旧规则不继续固化到实现或测试中。
- 后续编辑 renderer 前仍按 `AGENTS.md` 阅读相关文档以了解历史约束；冲突处以本次用户要求和本方案记录的决定为依据。收尾阶段同步整理旧文档，避免后续代理重新引用过时规则。
- 保留当前未提交工作。实施前记录 Git 状态与涉及文件的内容摘要；不能清理、覆盖或把已有修改自动归入本任务。
- 本轮范围包括列表、月、周视图，设置、编辑器、模板、搜索、帮助、业务弹窗、日期时间控件、提醒窗，以及桌面便签和原生截图工具的外观对应关系。
- 保留便签业务、数据模型、提醒规则、快捷键、窗口复用、壁纸与原生毛玻璃能力。样式改造不顺带改写这些功能。
- 标题栏已有苹果与微软两种模式继续可用；参考 macOS 不等于强制所有用户切换标题栏模式。
- 不重置用户字号、颜色、壁纸、便签外观与已保存窗口尺寸；不依据当前显示器反推或改写用户设置。
- 默认只做每阶段直接相关的局部测试及必要构建。全局 UI 改造不自动授权全量回归、打包、安装、提交或发布。

## 3 字号与缩放的实施规则

### 3.1 系统缩放与应用缩放

Windows DPI 负责把逻辑像素映射到不同显示器上的实际像素。Renderer 继续使用 CSS 像素，Electron 窗口和 Qt 工具沿用各自已有的 DPI 处理。不能再乘一次 `devicePixelRatio` 放大控件，也不根据屏幕分辨率猜测用户需要的字号。

应用保留三项不同职责：

| 项目       | 作用范围                                 | 目标行为                                                 |
| ---------- | ---------------------------------------- | -------------------------------------------------------- |
| 基础字号   | 沿用各视图现有字体设置及派生文字层级     | 改字大小时更新文字和必要的控件容纳空间                   |
| 界面缩放   | 拟新增应用级设置，覆盖主窗口及软件提醒窗 | 同时调整文字、图标、内边距及常规控件尺寸                 |
| 响应式布局 | 各内容容器                               | 窗口变宽显示更多内容，变窄调整排列，不自动把正文缩小一半 |

界面缩放拟使用 `appearance.uiScale`，默认 `1`，首版提供 90%、100%、110%、125%、150%。该名称、存储键和跨窗口分发需在 P3 核对现有设置架构后落实，不另建一套设置存储。缺失或非法值回退 100%，普通升级不覆盖合法旧设置。

桌面便签继续使用独立正文字号，灵动岛继续使用现有独立字号；Qt 截图工具首版继续按系统 DPI 保持工具尺度。设置说明必须明确应用界面缩放的覆盖范围，不声称已经缩放这些独立内容。它们的外观协调在 P6 单独验收。

### 3.2 保留 rem 的迁移方式

现有代码大量使用 `1rem` 约等于 `1px` 的设计约定。保留该数值体系，100% 界面缩放时根字号固定为 `1px`，拟采用如下关系：

```css
:root {
  --ui-scale: 1;
  font-size: calc(1px * var(--ui-scale));
}
```

正式实现需删除或重定向列表、月周与提醒入口中互相覆盖的根字号规则。不能只在文件末尾追加新规则，也不能把根字号直接改成 `16px`。

- `--font-size-base` 与备注字号仍由已有设置注入，保留数值及按视图保存的行为。当前列表与月周默认字号不同，是已有默认配置，不能为统一外观静默重置。
- 保留现有设置入口的字号范围：当前列表上限为 22，月周为 28。方案中的字号 28 常规场景用于月周；列表若注入该值做压力验证，需要标明这是测试条件，不顺带扩大设置功能。
- 同一字号设置、同一界面缩放下，同类组件在不同视图应具有相同的尺寸档位。用户主动选择的不同字号属于明确例外。
- 新增控件、菜单、辅助文字、标题、间距、圆角的语义变量，收拢页面内部重复的比例计算；正文的排版层级仍以用户字号为起点。
- 控件采用最小高度加内容撑开，避免大字号被固定高度截断。不得用重新缩小字体来抵消用户放大的设置。
- 细边线和焦点环使用稳定 CSS 像素。与原生窗口配合的 `--window-radius` 保留现有像素设置；不能只放大 CSS 圆角而让原生毛玻璃轮廓不变。
- 禁止在页面根部用 `transform: scale()` 或额外修改 Electron 页面缩放来替代这项布局迁移，避免可视尺寸与定位、命中区域分离。
- 梳理 JS 中所有 `rem → px` 换算、日期横条测量、浮层定位、标题栏命中区、侧栏拖动和灵动岛字体冻结路径。只更新受新尺寸模型影响的计算。

迁移完成后，在字号 17、界面缩放 100% 下，列表窗口从 480px 调至 720px，正文应仍为约 17 CSS px；改为 125% 界面缩放时，正文约为 21.25 CSS px。Windows DPI 调整改变设备像素呈现，不应再次改变这套计算结果。

### 3.3 兼容与恢复

新增缩放设置采用显式应用级作用域，验证三种视图切换、提醒窗同步、重启恢复和重置设置。标题栏已有图标缩放作为局部用户设置继续保留，并明确其与界面缩放的组合关系。

保留当前最小窗口边界与已保存几何信息。缩放到极端组合时，设置入口和“恢复 100%”必须仍可到达。不能通过扩大最小窗口或清除已保存尺寸掩盖布局问题。

## 4 响应式布局规则

先按容器可用宽度改造，再移除旧的自动缩字。每个阶段交付应能运行，避免根字号先固定、窄窗随后长时间不可用。

| 界面                 | 宽窗口                                         | 紧凑窗口与大字号                                                               |
| -------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------ |
| 列表与操作栏         | 内容区域伸展，卡片和正文保持字号；主要操作对齐 | 工具栏分行或使用明确的次级入口；筛选、排序、新建、设置可达；次要摘要优先让位   |
| 设置                 | 左侧名称、右侧控件，使用统一基线               | 单项按实际内容换行，控件可独占一行；标签与帮助仍能阅读；正文内部滚动           |
| 新建、编辑和模板表单 | 标签、输入与操作区对齐                         | 操作区可换行；正文滚动；保存、取消不被内容挤出或覆盖                           |
| 月周工具栏           | 日期导航位于内容区域中央，次要信息在两侧       | 导航和业务操作分行；减少非必要装饰与摘要占位                                   |
| 月周日历             | 根据可用空间排列日期格与便签横条               | 保留七天的日历语义；极窄时允许日历区域内部水平滚动，不把日期文字无限缩小       |
| 日期侧栏             | 空间足够时与日历并排                           | 空间不足时以覆盖面板展示，保留用户主动展开状态；关闭后回到当前日期与原滚动位置 |
| 模态与选择浮层       | 对齐触发器或所在操作区，限制最大阅读宽度       | 约束到可视区，内容内部滚动；必要时使用视口内的完整选择面板，保留清晰关闭入口   |
| 提醒窗               | 多条提醒纵向排列                               | 快捷时间与操作按钮换行，自定义时间区展开不挤掉确认操作                         |

列表容器初始候选分界为 360px、600px；月周工作区为 720px、1080px。这些是布局试验起点，最终断点需由实际内容、字号和缩放测量决定。优先采用容器查询、弹性换行和内容最小宽度，不给每个屏幕分辨率单独写样式。

滚动区域统一提供可发现的细滚动条与键盘滚动能力；浮层中的滚动不推动底层页面。测试需要检查滚动后的触发器位置、浮层重定位以及用户阅读位置保持。

## 5 公共外观与交互规则

### 5.1 颜色与材质

- 保留背景、正文、辅助文字、边线、主操作、强调、危险、警告和状态等不同职责。先按用途归类现有硬编码，绘图颜色、用户自定义文字颜色与品牌资源不做机械替换。
- 实心主按钮统一使用成对的背景与前景色；默认主蓝可继续使用 `#0071e3`，前景白色。交互强调与状态色按用途保留，不能仅因存在多个蓝色就全部合并。
- 为普通、悬停、按下、禁用定义同一组语义变量。危险按钮也定义专用前景配对，不能沿用任意正文色。
- 菜单采用稳定阅读表面，面板与模态用层级和必要阴影区分。玻璃效果集中在有空间语义的容器，内部控件保持清晰。
- 普通悬停优先使用一种主要反馈，避免填充、边框、阴影和位移同时增强。拖拽、图像预览等空间状态允许明确例外。
- 默认浅色、深色主题配对的普通文字目标对比度不低于 4.5:1，大号文字和必要控件轮廓不低于 3:1。用户自由选择的任意颜色组合不承诺自动合规，也不静默更改用户颜色；固定语义按钮必须自行保持可读。

### 5.2 按钮与开关

扩展 `BaseButton` 的主操作、次操作、危险操作、文字操作及图标操作能力；可增加小型包装组件，不按页面复制样式。保留原生按钮行为和属性透传，默认 `type="button"`，需要表单提交时显式声明。

首版尺寸候选为紧凑 26、常规 30、大号 34 个设计单位，均作为最小高度，随内容撑开。图标视觉尺寸与点击范围分开定义：常规点击范围至少约 28 CSS px，紧凑布局也不依赖极小图标本身作为完整命中区。

公共按钮负责禁用、加载、防重复操作、焦点环和按压反馈。业务请求的真实加载状态仍由调用方提供，不能只在视觉上禁用而保留提交入口。确认按钮前景不随正文色变化。

开关在组件内部提供 `role="switch"` 与 `aria-checked`，调用方负责明确的可访问名称。开启使用强调色，关闭使用中性轨道；拟采用实心滑块和清晰轮廓，与新方向配套。设置页紧凑尺寸作为明确变体，删除页面依赖内部类名修改滑块位置的重复规则。

焦点环不得仅靠全局低优先级规则兜底。普通、危险、图标、开关和输入控件都要验证最终计算样式；局部重置 outline 时必须提供可见替代。

### 5.3 选择器与菜单

建立公共浮层外壳和行为工具，统一定位、视口约束、层级、字体继承、生命周期与动画。可提取为 `useAnchoredPopover` 和公共浮层组件；名称在实施时结合现有目录确定，避免重复创建与 `anchoredPopover.js` 相同的工具。

| 类型               | 共同外观                                                                     | 专属行为                                                           |
| ------------------ | ---------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 普通单选与字号预设 | 一致的选项间距、圆角、字号档位；焦点或悬停用高对比强调填充；已选项用勾选标记 | 单选确认后关闭；字号输入保留自由输入和校验，预设支持点击与键盘     |
| 多选与提醒方式     | 共用菜单行、选中标识和焦点表达                                               | 切换选项后保持打开，不模仿单选自动关闭                             |
| 地区级联           | 共用面板材质和选项行                                                         | 保留多列级联、当前路径及列间键盘导航；不混同最终选中与当前浏览路径 |
| 日期与时间         | 共用浮层基础、头部与底部操作样式                                             | 保留各自即时选择或草稿确认规则；取消草稿不能意外提交               |
| 操作菜单           | 共用间距、材质和焦点规则                                                     | 保留菜单角色；危险项使用危险语义，不让普通蓝色覆盖危险含义         |

所有浮层统一满足：

1. 测量实际面板尺寸，优先贴近触发器，空间不足时翻转或限制内部滚动；底部确认操作始终可达。
2. Teleport 后显式传递字号、尺寸变体和必要的局部主题；不能依赖原父元素的 CSS 后代选择器。
3. 选择菜单支持上下方向键、Home、End、回车、空格与 Escape；日期网格按自身网格语义导航，中文输入法组合期间不误提交或误关闭。
4. Escape 优先关闭最内层临时面板，并返回触发器；外部点击关闭不抢走用户正在点击的新目标焦点。模态外壳继续遵守其业务关闭约定。
5. 单选菜单按 Tab 关闭并回到正常表单顺序；需要完整操作的对话式日期面板明确管理内部焦点。所属模态必须识别自己的 Teleport 面板。
6. 滚动、窗口缩放、界面缩放与触发器离开可视区时及时重定位或关闭；离场中的不可见内容不得继续截获输入。
7. 打开后禁用、父组件卸载、快速切换时释放监听、焦点归属与动画句柄；不会残留透明遮挡。

### 5.4 模态与非模态面板

优先复用 `AppModalShell`、现有焦点工具和模态队列。统一标题、关闭按钮、内容留白与底部操作区；确认框允许更紧凑的专用布局。

保留业务上的例外：通知确认规则、编辑未保存确认、子弹层、图片预览及独立业务排队，不为外观一致而统一成“点外部全部关闭”。这些例外应从组件参数和测试中明确表达。

## 6 动画规则

首次实施采用以下候选节奏，在同类组件之间统一，再根据真实录屏微调；调整后统一修改公共定义。

| 动作                     | 候选规则                                                          |
| ------------------------ | ----------------------------------------------------------------- |
| 悬停、焦点与颜色反馈     | 约 120ms，变化轻微                                                |
| 普通按钮按下与恢复       | 按下约 70ms，恢复约 160ms；轻微缩放或填充反馈，不额外跳动         |
| 菜单及日期时间浮层       | 约 180ms 进入、140ms 退出；短淡入和朝锚点的轻微位移，避免拉伸文字 |
| 设置、编辑器等工作面板   | 约 260ms 进入、220ms 退出，方向与布局关系一致                     |
| 日历换页、列表增删与重排 | 保留方向和位置连续性，使用已有业务语义；不强行改成菜单动画        |
| 刷新、处理中的操作       | 只在真实进行中播放状态动效，结束后停止                            |

- 普通选择菜单不强制使用旧文档的卷帘方式。统一采用上述锚点浮层动效；日期预览等确有方向语义的大面板可保留专用裁剪动画，并说明用途。
- 快速反向操作从当前显示状态继续，不能重新跳到全开或全关；取消回调不得结束新一轮动画。
- 定位翻转和动画方向共享同一个 placement 结果；不能仅改变 transform-origin 却继续使用反向裁剪。
- 页面离开、隐藏或组件销毁后停止不再需要的动画。动画不阻塞输入、业务完成或关闭请求。
- 去掉筛选图标的三圈装饰旋转与重复选择当前项的重播，保留明确的选中反馈。
- 本轮不新增动效偏好设置，也不借此次改造改写系统动效偏好的产品策略；记录现状，避免旧文档中的强制动效文字被当作新风格依据。

### 8.5 构建与执行环境

所有命令从仓库根目录执行。第一条 Node 命令即使用已配置运行时，并为派生进程设置 PATH：

```powershell
$uiNodeDir = 'C:\Users\Admin\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin'
$uiNodeExe = Join-Path $uiNodeDir 'node.exe'
$env:PATH = "$uiNodeDir;$env:PATH"

# 示例：仅执行 P2 涉及的既有单测文件
& $uiNodeExe '.\node_modules\vitest\vitest.mjs' run tests/styled-select-menu.test.js tests/pointer-anchored-popovers.test.js
if ($LASTEXITCODE -ne 0) { throw 'UI 局部单测未通过' }

# 有 renderer 改动需要真实应用专项时，先构建当前代码
& $uiNodeExe '.\node_modules\electron-vite\bin\electron-vite.js' build
if ($LASTEXITCODE -ne 0) { throw '当前代码构建未通过' }
```

- 每个阶段按实际文件运行 ESLint；例如用上述 Node 调用 `node_modules/eslint/bin/eslint.js` 并列出修改文件。必要的 renderer 构建不等于全量回归。
- 真实 Electron、GPU、桌面输入和 Qt 专项从一开始就在沙箱外执行，保留默认 Chromium 安全与 GPU 配置，使用临时用户目录和测试数据库。
- 单个 Electron 文件使用项目 Electron 可执行文件启动，并等待真实子进程结束、保存日志与退出码。Windows 启动独立测试进程时使用隐藏窗口启动选项；需测试界面显现的阶段由专项自身控制。
- 不无参数调用 `run-electron-window-tests.cjs`，其默认组是窗口专项集合；使用已验证的精确测试入口，不误跑全量或无关集合。
- Qt 外观变更先做必要的原生构建，再按 CTest 名称筛选相关测试；`native_capture/build.ps1 -Test` 会运行整个原生测试集合，不作为本方案的默认命令。
- 原生 DLL 与依赖 ABI 必须匹配当前源码。文件锁出现时先核实进程路径和命令行，仅处理本轮或确认可停止的项目进程。
