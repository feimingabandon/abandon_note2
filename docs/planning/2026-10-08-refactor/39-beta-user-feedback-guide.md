# BR-05：Windows 内测用户体验与反馈指引

日期：2026-10-10。状态：用户体验步骤和反馈模板已准备；当前仍有产品修改，固定候选与打包验收暂停，本阶段不生成安装包。本文没有预填候选包、安装结果、用户反馈或测试通过。以后交付负责人完成包内验收并填齐第 1 节后，才可将适用内容提供给测试用户。

本产品是单人使用的 Windows 10/11 x64 桌面便签软件。内测以正常使用为主：逐项体验自己会用的功能，遇到问题时保留可解释的现场。无需连续狂点、无限创建窗口或人为破坏文件。版本统一使用正常的 `1.4.0`；内测通过后，正式发布复用同一份已验证产物。

依据：[内测前收口指导](26-beta-readiness-guidance.md)、[候选验收章程](32-beta-acceptance-charter.md)、[安装与升级隔离指导](34-beta-installer-isolation-plan.md)、[运动诊断指导](25-window-motion-diagnostics.md)、[日志指南](../../LOGGING_GUIDE.md)、[截图多屏用户核验](../../testing/capture-multimonitor-user-checklist.md)。

## 2. 开始体验前

1. 确认 Windows 10/11 x64 和第 1 节候选身份。已有正式资料的用户，先按交付说明完成离线备份；复制资料前，从托盘选择 **退出应用**，确保应用已经完整退出。
2. 备份须覆盖负责人确认的资料范围，核对副本实际存在。不能根据产品名自行猜测资料目录；安装到另一个目录也不保证资料隔离。当前没有完整的产品级备份/恢复功能，便签报表不能代替数据库和附件备份。
3. 优先在独立测试资料或指定测试环境体验。真实旧版覆盖升级、回退和卸载由具备可恢复测试机器/虚拟机的测试人员按第 6 节完成，不让普通体验用户临时试探资料路径或清空资料。
4. 自建一组有辨识度的样本，例如正文以“内测-A”“内测-B”开头，并准备一张自绘图片。截图区域只展示这些样本或空白测试窗口。可以用样本标签“内测”。
5. 正常体验时保持 **日常记录**。遇到卡顿再按第 4 节短时开启深度。可以分几次完成以下步骤，不必一口气做完；未体验的功能直接记“未体验”。

以下截图操作明确使用 **保存** 或 **贴图**。截图选区中的 Enter、双击完成或复制操作可能覆盖现有剪贴板，因此本清单不要求这些动作，也不要求“剪贴板贴图”。图片附件使用点击选择或拖入自绘文件即可。

## 3. 自然操作与观察清单

每项操作后先看实际结果；方便时以正常速度再做两三次。有问题记录操作顺序和出现次数，不为凑次数持续触发同一故障。没有问题可记录已完成的具体步骤，无需写“所有功能正常”。

### 3.1 便签、编辑、附件与草稿

1. 在 **便签列表** 点 **新建**，填写一条中文、多行样本，选择一个分类标签，点 **创建便签**。再创建一条带自绘图片的便签，打开附件预览。
2. 右键样本选 **修改**，修改正文或附件，点 **保存修改**。看列表内容和图片是否同步；切到月/周视图再查看同一条样本。
3. 再打开 **修改**，输入一个明显的未保存标记，点 **放弃修改 / 关闭**。在 **放弃未保存的修改？** 中先选 **继续编辑**，确认刚才输入仍在；再次关闭并选 **放弃修改**，确认正式内容仍是上一次保存的版本。
4. 对一条样本操作 **标记完成**，再操作 **重新进行**；查看状态是否正确。便签中的 **置顶** 控制列表内顺序，与标题栏 **始终置顶** 的窗口层级分别观察。
5. 只删除一条自建样本。在 **删除便签？** 中确认后，普通列表、月视图和周视图应移除它。在搜索中开启 **包含已删除**，找到它并通过 **恢复便签** 恢复。核对正文、标签与附件；恢复后提醒保持关闭，已经关闭的桌面便利贴需重新贴出。

每条便签最多一个分类标签。未保存草稿的观察限于当前操作和应用已说明的范围；不把完整退出后的全部草稿恢复作为现有承诺。

### 3.2 三种列表和搜索

1. 依次体验 **时间线**、**自定义**、**标签分组**，观察刚才的新建、修改、完成、恢复样本。选好筛选条件后，核对样本数量和正文，避免把筛选后的隐藏当作丢失。
2. 在 **自定义** 中使用样本卡片的 **拖动排序** 手柄调整顺序。离开再回来，完整退出并重启后再看顺序是否保留。
3. 按样本关键词搜索，在同一条样本保存修改后再次查找；记录是否出现旧内容、重复项或不该遗漏的结果。
4. 若平时有超过一页的资料，使用自建样本或获准的离线测试副本浏览到下一页，再自然修改或调整一条样本的顺序，观察列表最终是否有重复、遗漏或顺序回跳。无需为此批量生成巨量便签；样本不够一页就注明这项未体验。

### 3.3 月视图、周视图与持续方式

1. 用 **生效时间** 创建昨天、今天、明天三条有辨识度的样本，保持系统日期不变。切换 **月视图** 与 **周视图**，使用 **上个月 / 下个月**、**上一周 / 下一周** 和 **定位到今天**，核对日期与样本归属。
2. 在完整新建/修改表单的 **持续方式** 中分别体验 **仅当天**、**指定天数**（设为 2 天）和 **持续到完成**。指定天数样本应在对应连续两天显示；持续到完成的未完成样本从生效日显示到今天，完成后以完成日期为结束日。
3. 使用 **展开日期列表 / 收起日期列表**，在日期侧栏修改或完成样本，观察日历和便签列表是否一致。跨日显示是一条便签覆盖多天，报表中不应变成多份正文。

### 3.4 循环模板

1. 从标题栏 **循环模板** 进入，点 **新建循环模板**。用样本正文，选择 **每天**，把 **生成时间** 设为方便观察的未来时刻，例如约 10 分钟后；核对 **下一次生成** 后点 **创建模板**。
2. 需要限定范围时设置 **开始时间** 和 **结束时间**，使下一次生成落在有效期内。体验期间保持程序运行，到时看真实便签是否生成一次、正文/标签是否正确。
3. 在模板卡片操作 **暂停**、**恢复**；核对显示状态。在月/周工具栏点 **显示循环便签预览 / 隐藏循环便签预览**，观察未来预览与已生成的真实便签能否区分。预览不是已经保存的便签，不计入日报选中记录。

无需修改系统时间来跨天或跨年；没有等到实际生成就注明只体验了配置与预览。软件完整退出期间不会运行后台任务，相关恢复情况按实际离线时间记录。

### 3.5 提醒

1. 新建一条 **生效时间** 约 10 分钟后的样本，在 **提醒方式** 选择 **软件内弹窗** 和 **托盘闪烁**。保持应用运行，观察是否在到期后提示正确样本；可从托盘 **查看便签提醒** 进入。
2. 对该样本选择 **5 分钟后**，看提示和下次到期表现。另一次可用 **自定义时间** 设置合理的未来时间，点 **稍后提醒**。测试完可用 **关闭本条** 收起该条提示；它与把便签 **标记完成** 的含义不同。
3. 对一条尚未到期的预约样本提前 **标记完成**，到原定时刻观察是否仍误提醒。不要据此期望 **重新进行** 会自动重发所有过去的通知。
4. 有条件再用另一条样本体验 **系统提醒**。记录 Windows 的通知权限、勿扰/专注助手状态和实际现象；系统通知没有出现时，分别记录软件弹窗、托盘和系统通知，便于判断投递环节。

不要求为测试关闭系统安全功能，也不把“尚未等待到期”记为通过。

### 3.6 便签报表

1. 点标题栏 **导出便签报表**，在 **便签报表** 中选择覆盖样本的两天 **日期范围** 和需要的状态。核对预览后取消勾选其中一条，记下 **已选择 N 条**。
2. 先选 **TXT**，点 **导出 TXT**，在 Windows 保存对话框保存到自建反馈目录；再选 **Excel**，点 **导出 Excel**，另存为另一个文件。
3. 在 **导出成功** 后用 **打开文件夹** 查看产物，独立打开 TXT；有可用表格阅读器时再打开 XLSX。核对中文、多行正文、所选样本、状态、日期，以及未选记录是否被排除。没有表格阅读器时，注明 XLSX 文件已生成但内容未读取。
4. 再发起一次导出，在 Windows 保存对话框点 **取消**。检查没有生成这次的新文件或出现误导性的成功提示。不要用覆盖已有文件来判断“取消有没有新文件”。

报表用于查看和交流选定便签，不包含完整恢复资料所需的全部数据库、附件和设置。

### 3.7 截图与贴图

1. 在设置的 **截图与贴图 → 截图** 查看当前快捷键；默认值为 F1，以实际设置为准。也可以从托盘 **截图** 进入。对自建样本窗口框选，明确点击 **保存**，另存到反馈目录并打开 PNG，核对选区范围、文字、边缘和尺寸。
2. 再次框选相同样本，明确点击 **贴图**。观察贴图位置是否贴合原选区，按正常速度拖动、用滚轮缩放；用 Ctrl+滚轮体验透明度，中键可恢复大小与透明度 100%。
3. 用贴图右键 **关闭 · Esc（可从托盘恢复最近一张）**，再从托盘 **恢复最近关闭的贴图** 恢复。用托盘 **显示/隐藏全部贴图** 观察已有少量贴图；无需创建大量窗口。
4. 再开始截图，按 Esc 取消，看主视图能否按 **截图时隐藏主视图** 的当前设置恢复。随后再开始一次并保存，观察取消后功能是否仍可用。
5. 已有多屏用户可选做：在自建样本上跨屏框选并保存 PNG，观察屏幕接缝处有无缺块、黑条、比例错误，再原位贴图核对位置。记录每个屏幕的缩放和排列；无需为体验安装虚拟显示驱动或改变已有配置。详细步骤见[多屏核验清单](../../testing/capture-multimonitor-user-checklist.md)。

### 3.8 快捷键、窗口、毛玻璃与贴边

1. 在设置核对 **视图显示快捷键** 和 **截图与贴图 → 截图**。体验显示/隐藏主视图、截图；按需录制一个自己方便的组合键，观察提示及保存后的实际行为。遇到冲突记录当前按键和提示，在释放冲突后用 **重试启用**，不必为造冲突去更改其他软件。
2. 在托盘勾选 **禁用全部快捷键（本次运行）**，观察快捷键停用、托盘状态；取消勾选同一项恢复。完整退出重启后，临时禁用状态应恢复，已保存的按键配置应保留。
3. 在当前主视图用标题栏选择 **始终置顶**、**正常层级**、**始终置底**，配合一个普通测试窗口观察实际前后关系。再按自己的习惯开启 **启用毛玻璃**，重复一次层级切换，观察正文和模糊背景是否一起移动、层级是否一致。系统/权限窗口和某些全屏窗口有各自的 Windows 规则，不要求压过所有窗口。
4. 用 **锁定主窗口 / 解锁主窗口** 观察移动和缩放；锁定时贴边自动隐藏停用。解锁后，在设置 **贴边隐藏 → 启用边缘** 中选一个自己能触达的上、左或右边缘，正常拖到该屏幕外边缘，鼠标离开后观察收起和唤出。
5. 按使用习惯分别体验 **隐藏后的唤出方式**：**直接唤出** 在触边后展开；**触边确认** 先出现小黑条、点击展开，离开后小黑条收回；**常显确认** 在收起后保持小黑条、点击展开，长按拖动可调整沿边位置。
6. 在另一主视图看它自己的外观和贴边设置。列表、月、周的这些设置分别保存；锁定、窗口层级和全局快捷键共享。多屏接缝不一定是可触达的屏幕外边缘，记录实际隐藏位置和屏幕排列。

原生毛玻璃可用性取决于 Windows 版本等条件。遇到不可用提示时保留提示与系统版本，不要求绕过限制。拖动/贴边出现卡顿时进入第 4 节，现场采集完成后即可停止反复触发。

### 3.9 桌面便利贴、关闭、退出与重启

1. 对自建便签右键 **贴到桌面**，在少量正常打开的便利贴中查看正文和附件、移动窗口；再次修改源便签时观察其显示是否同步。使用托盘便利贴相关入口管理这些样本，记录实际操作。
2. 点主窗口 **关闭**，确认只是隐藏到托盘；用托盘 **打开主窗口** 恢复。这个动作没有完整结束软件，提醒调度仍可能运行。
3. 保存样本后，先记下正文、标签、附件、列表顺序、窗口层级及当前视图配置。再从托盘选择 **退出应用**，等待完整退出，再正常启动，逐项对照保存结果和桌面便利贴的恢复情况。
4. 若在一次正常保存中很快选择退出，记录是否有等待、提示和最终保存结果。出现长时间无法退出时先保留时间与日志，不清空资料或反复强制结束进程。

## 4. 卡顿的短时深度采证

请区分“普通拖动不跟手”“贴边收起/展开卡住”“正文与模糊背景位置或层级不同”。问题在日常记录下先出现、开深度后消失或变重，也是一条有效反馈。

1. 先记下发生时间（尽量到秒）、当前视图、主窗口层级、**启用毛玻璃** 状态、贴边边缘与唤出方式，以及本次启动是否曾开启毛玻璃后又关闭。记录操作前屏幕和窗口所在位置。
2. 打开 **设置 → 查看日志**，在 **应用日志** 中点 **开启深度排查（10 分钟）**。确认显示 **深度排查 · 剩余 …** 后，关闭日志/设置浮层，再从新的一段拖动开始。中途开启深度可能缺少这段动作的完整前后记录。
3. 用刚才的自然动作复现几次：普通拖动、拖到已启用边缘、离开鼠标收起、按当前方式唤出。保持原有配置，观察鼠标、文字、背景分别怎么动；每次异常松开鼠标后立即记时间和是否还能继续操作。
4. 若方便，可只改变一个设置做一次对照，例如同一视图关闭/开启毛玻璃后重复同一路径；分别记录时间和配置。无需跑所有组合或持续狂点，也不用人为把电脑拖慢。
5. 返回 **设置 → 查看日志** 点 **停止采集**，确认回到 **日常记录**。然后点 **导出近一小时日志**，保存到自建反馈目录，并把文件名与刚才记录的时间对应起来。停止采集后仍可导出已保留的深度现场。
6. 若问题发生已超过一小时，可点 **导出全部日志**；“全部”指当前仍保留的日志。导出范围不受查看器搜索/级别筛选影响，导出本身不会开启深度。若显示 **部分诊断记录未能保留，导出文件会注明缺失情况。**，一并记录。
7. 仍未复现就停止采集，报告本轮持续多久、试了哪些动作及未复现。偶发问题可等下次自然发生后再开一轮；不要长期开深度等待。每轮默认 10 分钟，可 **延长 10 分钟**，单次最多 30 分钟；到期或采集保护触发会回日常，重启也回日常。

导出由用户主动操作，日志不自动上传，也不自动录屏。若愿意提供短录屏，先确保画面只有样本；反馈前查看画面和文件。日志有脱敏保护，但异常自由文本和历史记录不能保证绝对匿名，不应在测试正文中放真实私密资料。
