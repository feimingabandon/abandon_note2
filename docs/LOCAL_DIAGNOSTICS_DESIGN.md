# 本地问题诊断方案与验收

> 2026-09-28 双模式重构后，当前行为以 [日志系统维护指南](LOGGING_GUIDE.md) 为准。下文保留各阶段的历史实施与验证记录，其中默认详细采集、同步刷盘和旧容量描述不代表当前实现。

## 目标

用户描述现象并导出近一小时或全部保留日志后，可以追查：交互是否发生、业务请求是否到达、是否返回、数据库实际变化、通知是否送达、页面数据是否应用。不能把“没抛异常”当成功，也不承诺所有 Bug 自动确定根因。

不增加服务端、用户问题分类、问题标记按钮或录屏。现有两个导出按钮不变。“全部”是本地保留范围，不是无限历史（现有轮转：单文件 5 MB、总量 50 MB、14 天）。

## 实施

1. **原子关联**：诊断上下文随同一次 invoke 参数传输，主进程剥离后调用原处理器。异步上下文隔离并发操作，不依赖“最近一次点击”。保留同步返回及原异常；诊断不可影响业务。preload 仍为各入口独立文件，禁止 sandbox preload 共享运行时分块。
2. **客观结果**：记录 received / returned / failure，布尔 false、null、取消、明确拒绝和 no-change 保留实际语义。2 秒仍未完成记录 pending，不超时取消业务。窗口操作在主进程记录操作前后真实窗口状态；返回不等于原生视觉成功。
3. **持久化证据**：设置按实际作用域读 SQLite，比较序列化请求值与读回值；便签单条创建、保存、状态、删除/恢复/清除记录前后结构化快照和变化字段。只观察授权后的处理器，不改业务事务。读取或日志失败记 unavailable，不中止保存。
4. **界面证据**：全局控件交互记录静态控件标识、事件类型、所在页面，不采集输入内容；关键控件显式标识。交互与 IPC 没有明确传参关联时只提供时间顺序，不伪造因果。设置快照、便签广播携带上下文；记录接收以及设置 CSS 应用、列表和月周视图数据应用。广播触发的刷新保留合并原因，记录排队、开始、完成/失败/过期。
5. **隐私和体积**：新增快照不保存便签正文/备注/附件二进制；内容仅长度/摘要，列表最多 100 条 ID/版本摘要并标注截断。IPC 错误参数也过滤正文和凭据字段。已有异常 message/stack、第三方 console 可能含原始数据，导出不是绝对匿名文件，不采集原始 DOM 文本/键盘输入。

## 读日志的方法

按现象时间和窗口找到交互，再按 actionId 看业务调用。`received` 缺失意味着尚无主进程接收证据；`pending` 后无终态意味着可能卡住或进程终止；`returned` 仅证明接口返回。`settings.persisted` 的 mismatch 和 `note.persisted` 的 changedFields 提供实际数据库证据。`broadcast.sent` / `broadcast.received` / `view.refresh` / `view.data-applied` 分别表示发送、接收、刷新任务和 Vue 数据提交，不能相互替代。

一个广播可能导致多个监听器刷新；一个刷新可能合并多个广播。用 causeActionIds 列表表达，不归因到最后一条。无关联来源记录为空（例如启动/定时刷新）。日志缺失本身不是故障已证实。

## 验收矩阵

- 单元：并发与克隆失败不串号，false/null/拒绝/取消语义，异步上下文隔离，同步返回不变，pending 清理，诊断失败旁路，设置读回不一致，便签 no-change，内容脱敏，过期/失败/合并刷新记录。
- 专项 Electron：真实启动显示；设置写入与读回、便签创建/修改及页面应用；明确业务拒绝；真实按钮交互；保留近一小时/全部导出与历史会话过滤、sandbox preload 独立构建验证。
- 构建和变更文件 lint。仅运行本功能相关测试，不运行全量回归。

## 边界

本轮覆盖设置公共持久化入口、单条便签业务修改、主列表/月周视图、窗口 invoke 和语义控件交互。调度器/第三方服务、批量重排、所有原生拖动帧、便利贴独立数据库等仍利用已有日志，不宣称都具有同等数据库读回闭环。数据已应用不能证明无遮挡/颜色正确；屏幕异常仍需截图，崩溃或突然断电可能丢失最后未刷盘记录。

## 卡顿与滚动性能证据（2026-09-28）

用户只需正常使用，在卡顿后导出近一小时或全部日志，无需打开开发者工具。采集自动启用，沿用本地 JSONL、轮转和已有导出按钮，不上传。

- `performance.renderer-ready`：每个列表/月/周页面采集器的安装状态，包括 Long Task API 是否可用。
- `performance.renderer`：每 5 秒汇总滚轮、滚动和指针按下次数，输入排队延迟、交互到下一帧回调的延迟、帧回调间隔，以及大于 50 ms 的页面长任务。不读取 DOM 正文、输入值、按键字符或附件。监听为 passive，不取消事件，不修改现有惯性滚动。
- rAF 仅在交互及其后 1.5 秒内运行；闲置时停止。窗口隐藏时清空帧基线。超过 15 秒的观测间隔另记 `samplingGaps`，不把休眠、调试暂停和严重卡死混为掉帧；无法区分时保留证据，不猜根因。
- `performance.main`：1 秒轻量时钟检查主进程调度延迟；可见窗口最多每 5 秒采样进程资源和原生层级，空闲时每 30 秒写一条，Renderer 有汇总报告后短暂提高到采样频率。隐藏/最小化/锁屏/休眠时暂停资源采集。CPU 从各 PID 的累计 CPU 秒数差值计算，单位为一个逻辑核心的百分比，首个样本或进程更换后为 `null`，不是 0。GPU 进程 CPU 不等于 GPU 利用率。
- `nativeZOrder` / `nativeCounterDelta`：保存实际置底启用状态、桌面/Overlay 关系，以及同步请求、检查、无操作、实际重排的累计值和相邻采样差值；旧 DLL 没有计数器时差值为 `null`。不改变原生窗口行为。
- `performance.lifecycle` / `performance.observation-gap`：记录休眠/锁屏边界和不明长间隔，恢复后重建采样基线。导出系统快照附带最近最多 12 个资源样本；点击导出先提交 Renderer 尚未满 5 秒的批次，再固定导出时间范围。

分析时按会话、窗口、`intervalStart`/`intervalEnd` 和 `capturedAt` 对齐记录。帧回调变慢并伴随长任务，支持页面主线程阻塞方向；主进程延迟或实际重排计数突增支持相应方向。低 rAF 频率本身不能证明 GPU 或驱动故障，也不是实际呈现帧率。所有采集异常只影响诊断，不影响输入、业务或导出；系统信息仍仅在导出时采集，不在周期采样中运行 PowerShell/WMI。

定向验证包括聚合限频、后台/休眠采样重置、PID 更换、采集失败、观察器不支持、卸载和导出补交；Electron 日志专项包含真实滚轮输入及受控 Renderer/主进程长任务，并检查两种导出的性能记录。注入验证仅证明采集链路，不代表复现用户的 Windows 10 / Intel UHD 730 卡顿。

本轮验证结果：4 个定向单元测试文件（performance-diagnostics、error-capture、main-logging、diagnostic-noise-and-location），33 项通过；定向 ESLint、electron-vite 构建及 `git diff --check` 通过。真实 Electron `logging-actions` 专项最终退出码 0；证据目录 `tmp/test-runs/2026-09-28T04-29-43-137Z-0P834x/`，近一小时导出包含 241.4 ms 帧间隔、240 ms 长任务、346 ms 主进程调度延迟和导出前补交的滚轮批次。本机这次采样的主进程采集耗时最高 0.6 ms，不作为其他设备的性能保证。首轮测试容器位于滚动边界，调整为中间位置后验证实际滚动通过。未运行全量回归、安装包验证或用户硬件实测，未生成或发布安装包。

### 操作耗时归因补充（2026-09-28）

新增 `performance.operations` 和 `performance.render-work`，与前面的帧回调、主进程延迟和进程资源记录按时间对齐。采集默认启用，继续使用现有本地日志和两个导出按钮。

| 类别                            | 记录范围与解释                                                                                                                                                                                                                                                               |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ipc`                           | 除 `logs:*` 外的 invoke 通道：完成次数、仍在处理的数量、并发峰值、总/均/最大耗时、超过 50/100/250 ms 的次数、错误数、返回数组条数。`handlerSyncMs` 是处理器直接调用到返回值/Promise 的同步部分；`asyncRemainderMs` 还可能包含后续 JS 执行，不能视为纯 I/O 等待或主线程阻塞。 |
| `database`                      | 便签单条、列表、搜索、月周候选及标签/附件摘要读取，以及激活候选和到期模板读取。记录操作耗时与返回行数，不记录 SQL 或参数。查询函数耗时包含其同步结果组装，`toNoteListItems` 是其中的嵌套明细；返回行数不是 SQLite 实际扫描行数。                                             |
| `scheduler-check` / `scheduler` | 分别统计条件判断、任务同步执行，以任务名和 startup/scheduled/recovery/resume/manual-retry 区分来源；包含便签激活、模板生成/跳过/失败、实际通知数。成功但慢的任务也被记录。同步分发不会被误记为异步任务已完成。                                                               |
| `background`                    | 天气 `refreshIfDue` 从调用到异步完成的经过时间与失败次数；可能包含无需更新的快速返回。它与 scheduler 同步分发时间分开，其他网络请求不因此被宣称已覆盖。                                                                                                                      |
| `image`                         | 附件原图读取及 Base64 编码、尺寸解码、缩略图队列等待与同步解码/缩放、重复请求合并、缓存命中/未命中、字节数和像素尺寸。壁纸记录原图/裁剪图读取与缩略图耗时，读取时复用数据库中已保存的尺寸，不为诊断额外解码图片。                                                            |
| `logging`                       | 普通记录入队耗时/字节数/队列字节峰值，以及批量同步写盘耗时/文件数/记录数/失败和丢失记录数。入队包括序列化，达到队列阈值或 fatal 时也包括内联 flush。统计只在内存中更新，不从写盘函数再次调用 logger；性能日志不统计自己的入队，实际写盘仍计入下一批 flush。                  |
| `native`                        | JS 到 DLL 的材质应用、几何更新/同步等待、层级同步及置底调用的耗时、拒绝/异常次数。仅明确的原生初始化超时码或 Win32 ERROR_TIMEOUT 计入 `timeouts`；普通失败不推断为超时。异步 PostMessage 接口的耗时只代表提交，不代表原生线程处理完毕。                                      |
| `renderer`                      | 列表/月/周刷新次数、排队/合并/延后、加载结果、Vue nextTick 更新阶段、被新请求取代的更新，以及数据应用后到下一次帧回调的时间；帧请求合并、隐藏/卸载时取消。额外汇总便签溢出和日历容量布局测量的次数及耗时。                                                                   |

主进程汇总最多随资源日志每 5 秒写一次，空闲时每 30 秒；隐藏期间不为了归因额外轮询资源。主进程每会话最多 128 个操作键、每键最多 16 个数值字段，快照保留最近 3 批；Renderer 最多 48 个操作键，随已有 5 秒汇总输出。超出操作键上限记录 `omitted`。导出/退出会补交未满周期的统计，未完成操作跨批次保留 active，完成次数和全程耗时归到完成所在批次。操作可能相互嵌套，不能把所有 totalMs 相加当作 CPU 占用。

Renderer 仅在有操作统计待输出时读取 `.nl-card`、`.month-event-bar` 和 img 元素数量；这些是已挂载结构数量，img 也包含图标，不代表视口内附件数量。不读取文本、输入值、图片 URL 或样式，不增加逐帧 DOM 扫描；汇总自身的结构采集耗时单独记录。主进程窗口样本补充壁纸实际启用条件及 CSS 模糊半径。帧回调仍不等于实际画面呈现，布局测量回调也不等于完整 Layout/Paint 耗时；这些记录不能单独证实 GPU、驱动或 DWM 故障。
