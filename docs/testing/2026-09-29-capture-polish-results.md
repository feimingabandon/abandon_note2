## 实现行为

- 控件识别忙碌时，90ms 定时器补查鼠标最后的位置。请求编号和位置检查阻止旧结果覆盖新结果；框选或切回窗口识别后停止补查。无法识别子控件时保留窗口选区并提示可以手动框选。
- UI Automation 增加 400ms 的遍历预算检查，保留每次 COM 调用的超时设置。它限制继续遍历，不是强制终止单次第三方调用的绝对期限；最多一个后台查询线程，手动框选仍可使用。
- 颜色、字体、字号和各工具的线宽 / 效果强度保存在已有的 `capture-settings.ini`。每次截图仍从选择工具开始。撤销、重做、查看旧标注、旋转单个文字对象不会覆盖保存的偏好；不同贴图只更新用户主动修改的配置项。
- 复制成功显示短暂提示；保存成功显示实际路径；贴图缩放、透明度和恢复 100% 显示数值。提示是随引擎 / 贴图销毁的非交互装饰，不抢焦点，不修改导出的图片。
- 开始下次截图前立即隐藏反馈及工具提示，再同步桌面合成器。提示排除在自动窗口识别目标之外。
- 截图提示随选择、绘图、文字输入变化。更多菜单和贴图右键菜单提供操作说明；帮助窗口随截图 / 贴图关闭，不重复创建。

主要实现位于 `native_capture/engine/AnnotationEditor.*`、`CaptureOverlay.*`、`CaptureFeedback.*`、`CaptureEngine.*`、`PinWindow.*`、`SaveActions.*` 和 `platform/windows/DesktopTargets.*`。本轮未修改 `src/renderer`。

## 4K 绘制测量

使用 3840×2160 合成图，先绘制 12 个箭头，再模拟连续画笔 / 大面积马赛克 / 模糊拖动。预热 5 次后记录 60 次鼠标处理与图像合成耗时，最后比较预览和导出像素，并检查原始底图不变。

| 工具 | 中位数 | P95 | 最大值 |
| --- | ---: | ---: | ---: |
| 画笔 | 11.98ms | 12.92ms | 13.45ms |
| 马赛克 | 15.18ms | 16.16ms | 17.64ms |
| 模糊 | 16.76ms | 18.97ms | 19.27ms |

这是本机 CPU 路径的测量，不包含桌面最终呈现延迟，也不能证明所有机器稳定 60fps。审查时去掉了新增的逐次绘制工具栏重复布局，继续使用已有的状态变化信号更新提示。本轮没有改动像素合成算法或增加完整图像缓存。4K 大面积模糊仍有后续优化空间，暂未引入缓存失效和额外内存成本。

## 最终代码审查

对照本轮基线检查了接口调用、查询时序、配置写入、取消 / 销毁路径、提示窗口所有权、图像导出和测试可信度。检查点包括：

1. 所有截图 / 贴图入口都传递配置路径；未设置路径的独立测试保持不落盘。
2. 查询结果受请求编号、位置、工具状态约束；不会让异步结果覆盖已经确定的选区。
3. 只保存用户主动变更的参数；旋转、撤销 / 重做不回写旧对象参数。
4. 保存对话框返回仍检查父窗口与会话有效性，取消不误报成功；路径按纯文本呈现。
5. 提示由引擎或贴图所有，退出时清理；放大到屏幕外的贴图仍以自身屏幕上的可见部分定位提示。
6. 去除逐次绘制的重复工具栏布局；修正工具提示延迟隐藏和测试中的装饰窗口分类。

最终未发现本轮改动中未解决的阻断性问题。源码相对基线的空白检查无错误。这个结论只针对本轮范围，不代表已达到 Snipaste 全部免费版细节一致。
