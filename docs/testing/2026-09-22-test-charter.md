# 全量测试章程：业务、窗口系统、日志与叠加状态

用户要求：先写章程，再逐项仔细测试。本文先定义执行约束与验收标准；结果另记，不能用前一轮通过替代本轮执行。

## 1. 测试对象与边界

- 对象为当前工作区源码及其重新构建的 Windows x64 应用，包括已有未提交修改；保留现有暂存区，不提交、不发布。
- 业务链路覆盖 renderer → preload → IPC → SQLite/文件；窗口链路覆盖 renderer → 主进程状态 → Electron HWND → 原生边缘监视器/毛玻璃。
- 本机实测、故障注入、纯函数模拟、源码约束检查分别标注。模拟显示器变化/电源事件不等于真实拔屏/休眠；启用贴边配置不等于实际滑入屏外。
- 全量是本章程明确列出的全部项目与有限组合，不声称穷尽任意长度的操作序列。

## 2. 执行纪律与判定

1. 先记录 HEAD、暂存区和工作区状态、源码哈希、系统与显示器信息、工具版本。
2. 每个独立专项串行执行；前置构建失败则依赖项 blocked，其他独立项继续。窗口测试不得并行争夺桌面。
3. 使用明确的 Node 运行时和 PATH；真实 Electron、原生 DLL、GPU/DPAPI 与打包从第一条命令起在合适的桌面环境运行。
4. 仅用隔离测试数据库/用户目录；本地通知后台使用临时服务。不得触及生产数据、用户便签和现有应用进程。
5. 结果为 passed / failed / blocked / not-run。通过必须同时具备实际断言完成、进程结束及正确退出码；故意注入错误要单列预期，禁止删断言、跳过失败或吞错求绿。
6. 每次创建独立证据目录：命令、时长、退出码、stdout/stderr、JSONL、场景结果、失败状态快照。修复后新开复测目录，保留首次失败。
7. 发现缺陷后记录触发顺序、实际/期望与影响；沿用本任务已有修复授权修正确认的问题，重新构建并复测受影响项目。源码发生变化时重新核对验证基线。

## 4. 叠加状态与转换矩阵

### M1：实际贴边稳定循环

维度：列表/月/周 × 普通/置底/置顶 × 毛玻璃关/开 × direct/on-touch/persistent × 当前视图支持的每一条边。每个有效组合至少执行两次完整隐藏/恢复；验证原生物理位置在屏外、恢复可见、尺寸不漂移、会话 generation 正确、结束后暂停计数为 0。原生触发条的点击/悬停/拖动另由真实鼠标专项验证。

### M2：锁定和层级切换

每个视图、层级：锁定后不接受标题栏拖动、不自动贴边；解锁后恢复。实际隐藏/动画期间触发锁定、解锁、层级修改，检查命令明确成功或拒绝、无永久隐藏/卡住、不遗留旧监视器、状态与可见性可恢复。另保留置底→锁定→解锁→丢失指针捕获→连续拖动。

### M3：中断与恢复

分别从贴边隐藏中和动画中触发：禁用当前边、改变小黑条模式、切换视图、托盘打开、进入灵动岛、显示环境变化处理、电源边界处理、截图取消/崩溃。允许设计中的明确拒绝；拒绝不得破坏原状态。成功转换后不得残留隐藏会话、动画、暂停计数或不可操作窗口。

### M4：快速和重复操作

快速重复层级/锁定请求、隐藏→立即恢复、隐藏中重复打开、收缩/展开重入；验证节流/拒绝可解释、最终状态一致且可继续操作。每个子项单独记录，不以最终窗口出现代替过程断言。

### M5：日志叠加证据

矩阵运行时同步保存日志。故障注入有明确场景 ID；查证恢复事件、原生失败、截图退出及 IPC 终态。不能出现业务成功却持久化失败无证据、日志失败改变业务结果、日志泄漏便签正文等情况。

## 5. 共同通过条件

- 窗口：仍是预期 BrowserWindow/HWND；恢复位置在有效工作区，宽高不漂移；锁定/层级与实际原生状态相符；毛玻璃可用且同步。
- 贴边：隐藏时确实在屏外；恢复后无活动旧会话、悬挂动画/监视器和错误暂停计数；可以开始下一次隐藏/拖动。
- 业务：请求结果、数据库读回与文件字节一致；失败保留草稿/原数据，不发生误删除。
- 日志：记录可查询/导出，关联和脱敏正确；测试进程断言失败必须以非零退出。
- 性能：报告本机样本时间，不卡死/无限等待，不把单机样本当跨设备保证。

## 6. 实机条件与未覆盖项目

Windows 10、第二套 Windows 11 环境、真实多屏拔插/不同 DPI、显示驱动故障、物理休眠/锁屏、安装器覆盖升级与卸载需要对应环境。执行前盘点当前设备；缺少条件记 blocked/not-run，不能用事件模拟冒充。不得为测试突然锁定、休眠用户电脑或改变用户系统显示配置。目录包启动可验证打包资源，不能冒充安装升级通过。
