# 截图与贴图 v2：交互、视觉与代码审查

日期：2026-09-29。范围：当前 Qt v2 工作区实现；针对用户反馈的贴图位置、工具栏、图标与日常交互进行评估。**本轮没有修改产品代码、部署组件、提交或发布。** 新增审查报告与合成测试证据。此前 v1 差距报告中的“未实现”条目不能直接套用到当前 v2。

结论：当前已有截图、贴图和标注能力，但连续操作仍有明确缺陷，工具栏也缺少统一的视觉与信息层级。建议保留 C++/Qt 与 Electron 的分工，局部重构坐标传递、输入状态、文字变换和工具栏呈现。继续增加工具数量不能解决这些问题。

## 已确认的代码问题

以下均按 P2 记录；“优先处理”表示本轮建议修复次序。合成探针结果是缺陷复现证据，不是产品验收通过。

### R01 优先：截图贴出时丢失原始屏幕位置

- 位置：`native_capture/engine/PinWindow.cpp:59`；`CaptureEngine.cpp:387`；`PinWindow.cpp:109–119`。
- 截图转贴图只传裁剪后的文档，没有传选区的屏幕位置。新贴图直接 `move(QCursor::pos())`，把鼠标位置当作窗口左上角。
- 工具栏通常在选区下方。点击“贴图”时，鼠标位于工具栏，图片就从那里向下展开。这解释了用户观察到的“下半屏”；代码没有固定下半屏的布局规则。快捷键创建也会受当时鼠标位置影响。
- `constrain()` 只要求保留最多 32 逻辑像素可见，允许能放得下的图片仍大部分越出屏幕。
- 修复要求：区分截图转贴图、剪贴板贴图、关闭后恢复三种来源。截图保留选区屏幕矩形与视觉尺寸；剪贴板定义独立的初始放置策略；恢复使用保存的位置。显式转换物理像素与屏幕逻辑坐标，并处理负坐标、工作区和混合 DPI。
- 证据等级：源代码确定；本轮没有在真实多屏桌面复现位置。

### R02 优先：参数输入每个字符都会失焦

- 位置：`native_capture/engine/AnnotationEditor.cpp:276–298`，尤其第 295 行。
- 每次 `QSpinBox::valueChanged` 都执行 `canvas->setFocus()`，存在文字框时又把焦点送回文字框。
- 合成输入复现：输入前焦点为 `annotationSize`；输入第一个字符 `2` 后变为 `reviewCanvas`；接着按 `4`，数值最终是 **2，而非 24**。
- 修复要求：参数输入期间保留焦点，在明确提交/离开时恢复画布焦点；快捷键分派尊重数字框、文字和输入法状态。不能通过把所有测试按键直接发送给画布绕过焦点问题。

### R03 优先：第二笔擦除可能变成移动第一笔

- 位置：`native_capture/engine/AnnotationEditor.cpp:360–372`。
- 所有当前标注共享“命中包围盒就拖动旧对象”的逻辑。第二次擦除从前一次擦除的包围盒内开始，会进入移动旧对象，而不是开始新的擦除。
- 合成复现：第一笔从 `(100,100)` 到 `(200,200)`；第二笔从 `(150,150)` 到 `(240,150)`；结果仍只有 **1** 个擦除对象，第一笔起点 x 从 **100 变成 190**。已擦除区域可能随着旧擦除路径移走而重新显示标注。
- 修复要求：对连续画笔/擦除手势与对象选择、移动建立明确规则，避免用同一个包围盒命中逻辑无条件接管新笔画。画笔、荧光笔也需要一起检查，但本轮实际探针仅验证擦除。

### R04 优先：同一选区的复制结果与贴图结果可能不同

- 位置：`native_capture/engine/ImageDocument.cpp:231–241`、效果渲染第 99–115 行；`CaptureEngine.cpp:387`。
- 复制路径先渲染完整文档再裁剪（`CaptureOverlay.cpp:198`）；贴图路径先裁剪底图与平移标注，再重新渲染。选区边缘切过已有马赛克/模糊时，重新渲染会根据裁剪后边界重新取样，改变效果。
- 合成图：160×120 底图，效果区域 `(20,20)→(140,100)`，强度 12，裁剪 `(45,30,80,70)`。比较两条路径的 5600 个像素，马赛克 **5600** 个不同，模糊 **5594** 个不同。
- 修复要求：明确效果的源坐标、取样范围与裁剪语义，保证截图预览、无损复制/保存和初始贴图的可见像素一致，并保留约定的后续标注能力。不能仅为了通过比较而取消可编辑贴图。此证据只证明输出变化，没有证明敏感内容被还原。

### R05：文字控制框和实际文字变换不一致

- 位置：`native_capture/engine/AnnotationEditor.cpp:319–343`、第 426–440 行与 `layoutText()`；`ImageDocument.cpp:170–177`。
- 拖角只修改文字矩形，字号不变；合成测试把框宽从约 101 扩到 199，字号仍为 **24**。官方 Snipaste 基础操作将拖动文字框四角定义为调整文字大小。
- 当前文字旋转由数值框控制；控制手柄与点击命中仍用未旋转的包围盒，而绘制使用文字旋转。输入框也保持未旋转矩形。旋转后可见文字、命中区域与编辑预览无法统一。
- 修复要求：提供直接拖拽缩放/旋转，控制框、命中与文字排版共用变换模型；输入态与完成态切换时保持视觉位置。字号探针已复现，旋转错位为源码确认，真实 IME/旋转操作尚未复验。

### R06：工具切换丢失已经设置的线宽

- 位置：`native_capture/engine/AnnotationEditor.cpp:231–239`。
- 每次 `choose()` 都把普通绘图工具设为 3，效果/擦除工具设为 12。合成复现：矩形线宽 8 → 椭圆 → 矩形，回到 **3**。
- 修复要求：至少保证已调整参数在合理的工具切换过程中持续有效；明确共享参数与各工具参数的边界。这里是本产品的操作连续性建议，没有宣称免费 Snipaste 必须逐工具记忆全部颜色和参数。

### R07：部分快捷键与目标交互相反，状态约束也不完整

- `native_capture/engine/PinWindow.cpp:286–289`：当前 1 逆时针、2 顺时针；Snipaste 官方定义是 **1 顺时针、2 逆时针**。
- `CaptureOverlay.cpp:414–418`：Tab 总是走检测模式切换，没有编辑直线/箭头时的工具切换分支。
- `CaptureOverlay.cpp:439–473`、`PinWindow.cpp:342–354`：方向键移动选区/窗口前没有排除当前标注编辑状态。官方文档明确把移动选区/窗口限定在非编辑状态。这会让编辑与外层窗口控制争用同一按键。
- 修复要求：根据选区、对象编辑、文字输入、参数输入和贴图浏览状态集中分派按键，再写与目标语义对应的断言。本项是源码与官方文档对照，没有运行真实窗口焦点专项。

## 视觉和交互设计评估

以苹果设计原则组织视觉，以 Snipaste 核心行为组织操作；保留 Windows 使用习惯和便签产品的语义。Qt 能实现这些要求，现有问题不能归因于 Qt 本身。

| 方面 | 当前证据 | 建议 |
| --- | --- | --- |
| 图标 | `toolIcon()` 混合固定 24×24 位图绘制和 Segoe UI Symbol 字符；保存/快速保存同图标，来源动作共用 ↗；现有截图中轮廓、大小和视觉重量不统一 | 使用一套许可明确的 SVG 图标，统一线宽、端点、网格和光学居中，适配 DPI。不同语义使用可辨认的图形；不要直接搬用 Apple SF Symbols 资产 |
| 工具栏层级 | 复制/保存/贴图/取消位于开头，十余工具与历史动作紧密排布，其他输出散在尾部；完成动作不突出 | 稳定分为绘图、编辑、输出区域；突出“复制并完成”，贴图与保存有明确位置；低频业务动作进入更多菜单或来源区 |
| 参数 | 第二行常驻 HEX 下拉框、自定义颜色按钮和数值控件；文字时追加字体/角度；自定义颜色弹模态框 | 按当前工具展示相邻参数浮层，常用色块与宽度预览优先，数值/自定义色作为精确操作。避免选择工具后界面大幅跳动 |
| 材质与主题 | 原生组件硬编码米色表面、棕色边线，与宿主没有明确的主题映射 | 建立与便签语义色对应的原生主题层；克制圆角、细边线与阴影，在白色、深色、复杂图像背景上都可读。是否采用半透明材质取决于可读性和性能验证 |
| 状态与反馈 | 有悬停/选中样式，但工具提示混用“完成/关闭”等语义；所有工具都提示 Shift 约束 | 区分悬停、按下、选中、禁用、键盘焦点；提示与各状态实际行为一致；显示当前颜色和宽度，明确保存、关闭、销毁的结果 |
| 布局 | 固定最大 760 逻辑像素面板，空间不足时工具栏可能落入选区，与图像和手柄争位置 | 统一处理屏幕边缘、微小选区、全屏选区与参数浮层碰撞；保证完成操作可达、可隐藏且不遮挡当前操作对象 |

Apple 官方依据：工具栏应控制密度、按功能与频率分组、区分关键完成操作；图标应简单易识别、视觉一致、保持光学对齐并采用矢量格式。上述具体布局是本项目设计建议，非宣称必须逐项照搬 Apple 平台控件。

## 建议实施顺序和验收方法

1. **行为正确性**：原位贴图、参数焦点、连续擦除、裁剪效果一致。分别用鼠标按钮/Ctrl+T/中键验证位置；参数必须真实连续输入；图像路径做无损像素比较。
2. **编辑一致性**：统一事件状态，修文字变换、参数保持、键盘语义与退出层次。覆盖“框选→画箭头→改宽度→加文字→旋转→贴图→继续编辑→关闭→恢复”的连续流程。
3. **工具栏和图标**：先确定分组、主次动作和参数展开规则，再替换 SVG 与主题。截图和贴图共享视觉组件，动作语义按场景区分。
4. **局部验收**：100%/125%/150%/200% 缩放、显示器负坐标/混合 DPI，微小与全屏选区，白色/深色/复杂背景，中英文与真实输入法。进行 Snipaste 免费版的同动作实机对照，记录明确保留的产品差异。

继续遵守便签完整退出时截图快捷键、窗口与 helper 一同退出。本次不扩展 OCR、分组、跨重启历史等范围，也不建议整体换成外部截图应用。

## 本轮验证与边界

- 审查当前 C++ 实现、Qt 测试和前轮合成工具栏截图；读取 Apple HIG 与 Snipaste 官方文档。没有启动 Snipaste，不能称为两款软件的实机对照验收。
- 编译临时 `review_probe`，链接当前 `capture_ui.lib`/`capture_core.lib`（生成时间晚于本轮检查的相关源码）。MSVC/Qt 6.8.3，`QT_QPA_PLATFORM=offscreen`；最终构建及探针退出码均为 0。退出码表示观察程序执行完成，结果中记录的是上述缺陷。
- 探针覆盖参数焦点与连续输入、工具切换线宽、文字拖角、连续擦除，以及马赛克/模糊的裁剪一致性。只使用合成图片，无桌面读取、剪贴板写入或用户便签数据。
- 首次受限构建未识别 MSVC；切换沙箱外配置与构建后成功，不计为业务测试失败。
- 未运行全量测试、既有完整 Qt/Electron 专项、打包测试和性能基准；没有产品修改需要全局回归。多屏 DPI、真实工具窗口激活、IME、Windows 10、4K 长时绘图延迟仍待实机验证。源码存在全图重绘路径，但本轮未测性能，不声称已经复现卡顿。
- 前轮测试大量使用直接 `setValue()` 或指定画布发送按键，覆盖了功能输出，无法证明真实焦点与连续操作正确。因此此前通过结果不等于本次发现已被覆盖。
