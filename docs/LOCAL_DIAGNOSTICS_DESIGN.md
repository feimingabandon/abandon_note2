# 本地问题诊断方案与验收

## 目标

用户描述现象并导出近一小时或全部保留日志后，可以追查：交互是否发生、业务请求是否到达、是否返回、数据库实际变化、通知是否送达、页面数据是否应用。不能把“没抛异常”当成功，也不承诺所有 Bug 自动确定根因。

不增加服务端、用户问题分类、问题标记按钮或录屏。现有两个导出按钮不变。“全部”是本地保留范围，不是无限历史（现有轮转：单文件 5 MB、总量 50 MB、14 天）。

## 实施

1. **原子关联**：诊断上下文随同一次 invoke 参数传输，主进程剥离后调用原处理器。异步上下文隔离并发操作，不依赖“最近一次点击”。保留同步返回及原异常；诊断不可影响业务。preload 仍为各入口独立文件，禁止 sandbox preload 共享运行时分块。
2. **客观结果**：记录 received / returned / failure，布尔 false、null、取消、明确拒绝和 no-change 保留实际语义。2 秒仍未完成记录 pending，不超时取消业务。窗口操作在主进程记录操作前后真实窗口状态；返回不等于原生视觉成功。
3. **持久化证据**：设置按实际作用域读 SQLite，比较序列化请求值与读回值；便签单条创建、保存、状态、删除/恢复/清除记录前后结构化快照和变化字段。只观察授权后的处理器，不改业务事务。读取或日志失败记 unavailable，不中止保存。
4. **界面证据**：全局控件交互记录静态控件标识、事件类型、所在页面，不采集输入内容；关键控件显式标识。交互与 IPC 没有明确传参关联时只提供时间顺序，不伪造因果。设置快照、便签广播携带上下文；记录接收以及设置 CSS 应用、列表和月周视图数据应用。广播触发的刷新保留合并原因，记录排队、开始、完成/失败/过期。
5. **隐私和体积**：新增快照不保存便签正文/备注/附件二进制；内容仅长度/摘要，列表最多 100 条 ID/版本摘要并标注截断。IPC 错误参数也过滤正文和凭据字段。已有异常 message/stack、第三方 console 可能含原始数据，导出不是绝对匿名文件，不采集原始 DOM 文本/键盘输入。

## 读日志的方法

按现象时间和窗口找到交互，再按 actionId 看业务调用。`received` 缺失意味着尚无主进程接收证据；`pending` 后无终态意味着可能卡住或进程终止；`returned` 仅证明接口返回。`settings.persisted` 的 mismatch 和 `note.persisted` 的 changedFields 提供实际数据库证据。`broadcast.sent` / `broadcast.received` / `view.refresh` / `view.data-applied` 分别表示发送、接收、刷新任务和 Vue 数据提交，不能相互替代。

一个广播可能导致多个监听器刷新；一个刷新可能合并多个广播。用 causeActionIds 列表表达，不归因到最后一条。无关联来源记录为空（例如启动/定时刷新）。日志缺失本身不是故障已证实。

## 验收矩阵

- 单元：并发与克隆失败不串号，false/null/拒绝/取消语义，异步上下文隔离，同步返回不变，pending 清理，诊断失败旁路，设置读回不一致，便签 no-change，内容脱敏，过期/失败/合并刷新记录。
- 专项 Electron：真实启动显示；设置写入与读回、便签创建/修改及页面应用；明确业务拒绝；真实按钮交互；保留近一小时/全部导出与历史会话过滤、sandbox preload 独立构建验证。
- 构建和变更文件 lint。仅运行本功能相关测试，不运行全量回归。

## 边界

本轮覆盖设置公共持久化入口、单条便签业务修改、主列表/月周视图、窗口 invoke 和语义控件交互。调度器/第三方服务、批量重排、所有原生拖动帧、便利贴独立数据库等仍利用已有日志，不宣称都具有同等数据库读回闭环。数据已应用不能证明无遮挡/颜色正确；屏幕异常仍需截图，崩溃或突然断电可能丢失最后未刷盘记录。
